    400 js, react (요청 자체 문제) 
    500 backend(요청 정상, 서버문제)

    Dom: html을 객체로 만들어주는, html과 js
    api: 프로그램과 연결하는 인터페이스, html과 java
    캐싱: 한번 방문했던 사이트 특정파일을 브라우저에 저장하고 다음에 방문할때 서버에 저장된 파일을 사용하는 기술
    SPA: 처음 단 하나의 HTML페이지 받아오고 다른 메뉴 클릭해도 페이지 전체를 새로 불러오지않음
    
    JSX: HTML + JS 혼합문법 제공
    JSP: HTML+JAVA 혼합문법 제공

    node.js: java처럼 js가 혼자서 실행가능한 환경(런타임)
    npm: 스프링 gradle처럼 외부 라이브러리 설치/관리 프로그램
        - node.js에 npm포함

    cd.. : 폴더 뒤로가기

    component: 화면을 구성하는 최소단위
        - 각 component는 자신만의 state 상태를 가질 수 있음. 즉 data를 가질 수 있음
        - 상태가 변하면 화면은 새롭게 렌더링되며 변경됨
    
    jsx: js안에서 html과 유사한코드를 사용하는 확장 문법(가상 html 문법)
        - CSR 전용 문법
        - jsx코드는 최상위 요소로 감싸야함
        - xml문법을 따르므로 여는태그와 닫는태그가 모두 필요
        - class->className, onclick->onnClick 등

    props: 컴포넌트간 데이터를 주고받을때 props 사용
        - 객체이다
        - 부모 -> 자식 데이터를 전달할때 props를 사용
        - 값, 배열, 객체, 함수 등 다양한 데이터 담아 전달 가능
        - 읽기전용, 부모컴포넌트에서만 값 수정/조작 자식컴포넌트에서는 수정x
        방법 1: porps 매개변수
        방법 2: 필요한값만 구조분해할당
    
    react 이벤트 처리
        사용자 인터렉션이 발생했을 때 이벤트 핸들러로 전달. 이 과정에 react는 브라우저의 기본 이벤트를 사용하지않고
        합성이벤트(synthetic Event)라는 객체 생성해 핸들러 함수로 전달
        1. 이벤트 핸들러 이름은 카멜
        2. 함수로 전달 (실행x)
        


1. node_modules: 설치된 라이브러리 모은 폴더
2. public: img/js/동영상/logo 정적 파일 모은 폴더
3. src->main.jsx: 리액트 실행 진입점 파일
4. index.html: 리액트는 SPA(싱글 페이지 어플리케이션)이라서 HTML이 1개
5. pakage.json: 설치전 라이브러리(의존성) 담고있는 파일
- 리액트 시작: npm run dev

재귀함수: 현재 실행되는 함수가 함수내 다시 호출되고 반환되는 구조
콜백함수: 함수에게 함수 전달해 나중에 함수 실행 + 메소드 레퍼런스

React를 사용하는 이유
1. 컴포넌트화: ex) 큰 물건에 대해 작은 부품으로 나누기
2. 재사용: 한번만든 컴포넌트를 여러곳에 적용
3. 상태관리(state): 사용자의 행동에 따라 변하는 데이터 관리가 편함
